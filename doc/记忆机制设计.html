二、升级方案

方案 A：记忆压缩（短期，1 天）

当对话轮数超过阈值时，用 LLM 对历史做一次摘要压缩，保留关键信息而不是简单截断。

用户提问 → 检查历史 > 10轮？ → 是 → 调用 LLM 压缩旧对话 → 存入 compressed_summary → 保留最近 5 轮 + 摘要 
// memory.py 新增
def summarize_history(session_id: str) -> str:
    history = get_all_history(session_id)
    if len(history) <= 5:
        return ""
    # 调用 LLM 压缩
    summary = llm.invoke(f"压缩以下对话为 100 字摘要：{history[:-5]}")
    save_summary(session_id, summary.content)
    return summary.content
优点缺点
实现简单，2~3 个函数需要额外 LLM 调用，增加成本
token 消耗大幅降低摘要可能丢失细节

方案 B：向量记忆召回（中期，2 天）

每轮对话做 embedding 存入 ChromaDB，新问题来的时候用语义相似度召回相关历史，而不是只看最近的 N 轮。

用户提问 → ChromaDB 检索相似历史 → 召回 top-3 相关对话 → 拼入 prompt 
# memory.py 新增
def save_to_vector(session_id, query, answer):
    text = f"用户：{query}\nAI：{answer}"
    vectorstore.add_texts([text], metadatas=[{"session": session_id}])

def recall_memory(query, session_id, k=3):
    docs = vectorstore.similarity_search(query, k=k, filter={"session": session_id})
    return [d.page_content for d in docs]
优点缺点
语义召回，不依赖顺序需要 embedding 模型（可复用已有 ChromaDB）
用户问"之前说的那个问题"也能命中首次 embedding 有延迟

方案 C：Agent 主动记忆（长期，3 天）

Agent 通过工具主动决定"这件事值得记住"，而不是被动记录所有对话。类似 MemGPT/Letta 的思路。

class RememberTool(BaseTool):
    name = "remember_this"
    description = "记住一条重要信息供后续参考"
    def _run(self, key: str, value: str):
        memory_store[key] = value
        return "已记住"

class RecallTool(BaseTool):
    name = "recall_memory"
    description = "回忆之前记住的信息"
    def _run(self, query: str):
        return vectorstore.similarity_search(query)

场景示例：

用户：S-07 的通风管道上个月维修过
Agent：→ 调用 remember_this("S-07通风管道维修", "2024年3月维修过")
    ↓
两周后：
用户：S-07通风有什么要注意的？
Agent：→ 调用 recall_memory("S-07通风")
    → 返回"2024年3月维修过通风管道"
    → 回答时主动提及

三、推荐路线

优先级方案时间面试价值
P0方案 A：记忆压缩0.5 天⭐⭐⭐
P1方案 B：向量召回1 天⭐⭐⭐⭐⭐

建议：先做 P0（压缩）+ P1（向量召回），这两个可以共用已有的 ChromaDB 基础设施，性价比最高。做完后面试可以讲：

"我实现了多级记忆系统：短期记忆用滑动窗口保留最近 N 轮，长期记忆用向量库做语义召回，支持跨会话关联。每个记忆条目有时间戳和关联的 Agent 信息，Agent 也可以通过工具主动决定什么值得记住。"
