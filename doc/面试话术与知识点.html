🎯 面试介绍话术与知识点

粮库多智能体系统 · 面试准备指南

一、自我介绍话术（1 分钟版）

"我做了一个粮库仓储多智能体系统，基于 LangChain + LangGraph 搭建了 5 个专业 Agent（粮情分析、智能作业、出入库、质量检测、报表分析），通过状态机编排替代传统 if-else 路由。

主要亮点包括：RAG 知识库让 Agent 能检索国标文档，Hybrid Search 融合向量和关键词召回；多级记忆系统用 SQLite + ChromaDB 做对话持久化和语义召回；以及 Agent 辩论机制让多个 Agent 独立分析后投票决策。

技术栈用了 DeepSeek API、FastAPI 流式 SSE 前端实时展示推理过程，完整代码在 GitHub 上。"

二、逐技术点深挖

2.1 Multi-Agent 架构 高频

面试官问：为什么要用多 Agent 而不是一个 Agent 做所有事？

"单一 Agent 的 prompt 太长会导致注意力分散，工具选择准确率下降。我把粮库业务拆成 5 个垂直 Agent，每个只有 3~6 个工具，prompt 聚焦，调用准确率更高。同时多 Agent 支持并行执行，整体响应更快。"

对应知识点：

Agent 设计原则单一职责、prompt 聚焦、工具数量控制
Orchestration 模式Centralized vs Decentralized
并行 vs 串行asyncio.gather 并发执行

2.2 LangGraph 状态机 高频

面试官问：为什么用 LangGraph 而不是普通 if-else？

"手写 if-else 编排的问题在于扩展性差——新增一个 Agent 要改路由逻辑。LangGraph 用 StateGraph 定义节点和有向边，每个 Agent 是一个 Node，路由由 LLM 或条件函数决定，新增 Agent 只需注册一个新 Node 和对应边。"

对应知识点：

StateGraph节点(Node) + 边(Edge) + 状态(State)
条件路由add_conditional_edges
与 LangChain 关系LangGraph 是 LangChain 的编排层
LangGraph vs AgentScopeLangGraph = 状态机编排（单进程轻量）；AgentScope = 分布式运行时（阿里系）

2.3 LangGraph vs AgentScope（追问备选）

面试官可能追问：LangGraph 和 AgentScope 有什么区别？为什么选 LangGraph？

"AgentScope 是阿里达摩院的多 Agent 分布式框架，适合大规模生产部署。但我的项目是单进程多 Agent，LangGraph 更轻量，概念清晰，且 LangChain 生态的工具链更成熟。如果以后需要分布式部署，可以换成 AgentScope 或自建消息队列。"

对比速记：

维度LangGraphAgentScope
定位状态机编排分布式 Agent 运行时
通信State 共享Msg 消息队列
并行0.3+ 支持原生分布式
社区大（LangChain 生态）小（主要国内）
面试推荐✅ 通用阿里系可提

2.4 RAG 知识库 高频

面试官问：RAG 怎么实现的？为什么用 Hybrid Search？

"国标文档里专业术语很多，纯向量检索对'容重≥790g/L'这类精确匹配效果不好。我加了 BM25 关键词检索做 Hybrid Search，两个检索器各占 0.5 权重融合结果，兼顾语义相似度和关键词精确匹配。"

对应知识点：

Embedding 模型text-embedding-3-small
Chunk 策略chunk_size=512, overlap=50
Hybrid Search向量检索 + BM25 加权融合
ChromaDB持久化向量数据库

2.5 记忆系统 高频

面试官问：Agent 怎么记住之前的对话？

"我做了三级记忆：短期用 SQLite 存最近 N 轮对话，超阈值时用 LLM 压缩成摘要；长期用 ChromaDB 做向量存储，新问题来的时候语义召回相关历史。每次 Agent 调用时，历史上下文 + 压缩摘要 + 语义召回结果一起拼入 prompt。"

对应知识点：

短期记忆滑动窗口 + 注入 prompt
长期记忆向量库存储 + 语义召回
记忆压缩LLM 摘要压缩
SQLite vs 向量库结构化 vs 非结构化存储

2.6 Agent 辩论机制 进阶

面试官问：怎么保证 Agent 回答的准确性？

"单个 Agent 可能出错，我实现了辩论机制——多个 Agent 独立分析同一问题，各自输出结论 + 置信度，然后加权投票。比如通风条件判断，粮情分析、智能作业、质量检测各投一票，最终结果比单 Agent 更可靠。前端还画了柱状图展示投票分布。"

对应知识点：

Ensemble 思想多模型集成减少偏差
加权投票置信度作为权重
结构化输出Agent 返回 JSON 格式结论

2.7 可观测性 进阶

面试官问：怎么追踪和调试 Agent 的行为？

"每个请求分配 trace_id，贯穿前端→API→编排器→Agent→Tool。所有 LLM 调用和工具调用都记录到 SQLite，包括 Token 数、耗时、成功状态。前端还能查看工具调用的 DAG 图，直观看到 Agent 的推理链路。"

对应知识点：

分布式追踪trace_id + 全链路日志
Token 计量估计 tokens + DB 记录
DAG 可视化有向无环图展示调用链

2.8 流式 SSE 进阶

面试官问：前端怎么实时展示推理过程？

"后端用 FastAPI StreamingResponse 做 SSE，每次 Agent 开始/完成/调用工具时 yield 一个事件。前端收到 thinking 事件就显示'分析中...'，收到 tool_calls 就显示调了哪些工具，收到 agent_done 就显示耗时。用户不用干等，体验好很多。"
SSE vs WebSocket单向流 vs 双向通信
Event Stream 格式data: JSON\n\n
前端 EventSourcereadable stream 读取

三、面试官可能追问的问题

问题参考答案
DeepSeek 和其他模型比有什么优劣？便宜、支持 function calling、V3 响应快；但 V4 Flash 推理模型不支持工具调用
RAG 检索准确率怎么评估？没有正式做 RAGAS 评估，但通过 Hybrid Search 提升了术语匹配准确率
为什么不用 LangChain 的 ConversationBufferMemory？因为它只在内存里，重启丢数据；我用 SQLite 持久化，还加了向量召回
Agent 调用工具失败怎么处理？LLM 调用失败自动重试 2 次（指数退避），工具本身是本地 mock 不会失败
这个项目你做了多久？核心功能约 2 周，后续不断迭代加入 RAG、记忆、辩论等进阶功能
有没有做测试？单元测试用 pytest 覆盖了 Tool 层和编排器，CI 自动跑
部署方案？docker-compose 一键部署（API + ChromaDB）
