# 粮库仓储多智能体系统 — 需求设计文档

## 1. 文档概述

### 1.1 项目背景

粮食仓储管理涉及粮情监测、出入库作业、通风/熏蒸/控温等智能作业、库存盘点、报表统计等诸多环节，人工管理效率低、响应慢、易出错。本项目旨在构建一套 **多智能体（Multi-Agent）粮库仓储系统**，以 **AgentScope** 为多智能体编排框架，各子智能体基于 **LangChain** 实现，实现对粮库全流程的智能化管理与协同。

### 1.2 项目目标

| 目标 | 说明 |
|------|------|
| 粮情实时感知 | 自动采集温度、湿度、虫害、气体等数据，异常预警 |
| 作业智能调度 | 根据粮情自动规划通风/熏蒸/控温等作业方案 |
| 出入库全流程管理 | 从预约、质检、称重、入库/出库到结算的闭环 |
| 报表自动生成 | 日报、月报、年报及自定义报表的智能生成与分析 |
| 多智能体协同 | 各子智能体通过 AgentScope 实现消息传递与任务编排 |

### 1.3 技术栈

| 层级 | 技术选型 | 说明 |
|------|---------|------|
| 多智能体编排 | **AgentScope** | 负责 Agent 注册、消息路由、任务编排、共享记忆 |
| 子智能体框架 | **LangChain** | 每个子智能体内部的工具调用、Chain 编排、LLM 集成 |
| LLM 底座 | GPT-4 / 通义千问 / DeepSeek | 根据部署环境选择 |
| 数据存储 | PostgreSQL + InfluxDB (时序) + MinIO (文件) | 结构化/时序/非结构化分离 |
| 消息中间件 | RabbitMQ / Redis Stream | Agent 间异步消息 |
| 前端 | React + Ant Design + ECharts | 管理界面 + 可视化大屏 |
| 部署 | Docker + Kubernetes | 微服务化部署 |

### 2.2 AgentScope Orchestrator 核心职责

| 职责 | 说明 |
|------|------|
| **Agent 注册中心** | 维护所有子 Agent 的元信息（名称、能力描述、当前状态）|
| **任务分解与分发** | 将用户请求拆解为子任务，分派给对应 Agent |
| **消息路由** | Agent 之间的消息传递（同步/异步/广播）|
| **共享记忆** | 全局上下文记忆（仓库状态、当前任务链、环境参数历史）|
| **冲突消解** | 当多个 Agent 的决策冲突时（如作业建议 vs 安全约束），由 Orchestrator 裁决 |
| **结果聚合** | 将各 Agent 的输出合并为统一的用户响应 |

## 3. 子智能体详细设计

### 3.1 粮情分析 Agent (GrainConditionAgent)

#### 3.1.1 职责

实时采集并分析粮仓内的温度、湿度、水分、虫害密度、气体浓度（CO₂、PH₃）等参数，输出粮情状态评估、异常预警和发展趋势预测。

#### 3.1.2 LangChain 实现结构

```
GrainConditionAgent
├── Chain: 粮情分析链
│   ├── Step 1 — 数据采集 (Tool: 查询传感器当前值)
│   ├── Step 2 — 时序分析 (Tool: 查询 InfluxDB 历史趋势)
│   ├── Step 3 — 异常检测 (LLM: 判断是否超阈值)
│   ├── Step 4 — 分级预警 (LLM: 正常/关注/警告/严重)
│   └── Step 5 — 报告生成 (LLM: 自然语言总结)
├── Tools:
│   ├── get_sensor_latest(silo_id) → 当前读数
│   ├── get_sensor_history(silo_id, time_range) → 时序数据
│   ├── get_threshold_config(silo_id) → 预警阈值
│   └── get_grain_type(silo_id) → 粮食品种 (不同品种阈值不同)
└── Memory:
    └── 窗口记忆: 保留最近 24h 的分析结论，用于趋势判断
```

#### 3.1.3 核心指标

| 指标 | 传感器类型 | 正常范围 | 预警阈值 |
|------|-----------|---------|---------|
| 粮温 | 热电偶阵列 | -10~30°C | >35°C 或异常温升 >1°C/天 |
| 仓温 | 温湿度计 | -20~45°C | 与粮温差 >10°C |
| 湿度 | 湿度传感器 | 40~70% RH | >75%RH 持续 3 天 |
| 水分 | 水分传感器 | 存储安全水分以下 | >13.5%(稻谷) / >14%(小麦) |
| 虫害 | 诱捕器+AI识别 | <5头/kg | >10头/kg |
| CO₂ | 气体传感器 | <500ppm | >1000ppm |

#### 3.1.4 输出格式

```json
{
  "silo_id": "S-01",
  "timestamp": "2025-06-15T08:00:00Z",
  "overall_status": "normal",          // normal | attention | warning | critical
  "metrics": {
    "temperature": { "value": 22.3, "unit": "°C", "status": "normal", "trend": "stable" },
    "humidity":    { "value": 65.0, "unit": "%RH", "status": "normal", "trend": "rising" },
    "pest_density": { "value": 3, "unit": "head/kg", "status": "normal", "trend": "stable" }
  },
  "alerts": [],
  "suggestion": "当前粮情正常，建议保持现有通风策略。"
}
```

### 3.2 智能作业 Agent (IntelligentOperationAgent)

#### 3.2.1 职责

根据粮情分析结果和作业计划，自动生成通风、熏蒸、控温、翻仓等作业方案，协调设备执行，并监控作业过程。

#### 3.2.2 LangChain 实现结构

```
IntelligentOperationAgent
├── Chain: 作业决策链
│   ├── Step 1 — 读取粮情 (接收粮情 Agent 的输出)
│   ├── Step 2 — 判定作业类型 (LLM: 需要哪种作业？)
│   ├── Step 3 — 方案生成 (LLM: 参数计算 + Tool: 获取气象/电价)
│   ├── Step 4 — 安全校验 (Tool: 检查设备状态 + LLM: 约束检查)
│   ├── Step 5 — 审批请求 (通知管理员 / 自动执行规则)
│   └── Step 6 — 执行监控 (Tool: 控制PLC + 回传执行状态)
├── Sub-chains:
│   ├── VentilationChain     — 自然通风 / 机械通风方案
│   ├── FumigationChain      — PH₃ 熏蒸方案 (安全优先)
│   ├── TemperatureControlChain — 空调/谷冷机控制
│   └── TurningChain         — 翻仓作业计划
├── Tools:
│   ├── control_device(device_id, command, params) → 设备控制
│   ├── get_weather_forecast() → 未来 72h 气象
│   ├── get_electricity_price() → 峰谷电价
│   └── get_device_status(device_id) → 设备在线/故障
└── Memory:
    └── 方案记忆: 保存历史作业方案及效果评估
```

#### 3.2.3 通风作业规则示例

| 条件 | 建议作业 |
|------|---------|
| 粮温 > 目标温度 + 5°C，且大气温湿度适宜 | 机械通风 |
| 仓内湿度 > 75%，且大气湿度 < 60% | 自然通风（排湿）|
| 粮温分层明显，温差 > 3°C | 翻仓或通风均温 |
| 冬季大气干冷 | 机械通风降温（节能时段）|
| 夏季高温高湿 | 暂停通风，开启空调控温 |

#### 3.2.4 输出格式

```json
{
  "operation_id": "OP-20250615-001",
  "type": "ventilation",
  "sub_type": "mechanical_ventilation",
  "target_silos": ["S-01", "S-02"],
  "plan": {
    "start_time": "2025-06-15T22:00:00Z",
    "duration_minutes": 120,
    "fan_speed": "medium",
    "airflow_direction": "bottom_up"
  },
  "safety_check": { "passed": true, "notes": "设备在线，满足通风条件" },
  "approval_required": false,
  "estimated_cost": { "kwh": 45, "cost_yuan": 31.5 }
}
```

### 3.3 出入库 Agent (InOutBoundAgent)

#### 3.3.1 职责

管理粮食入库和出库的全流程，包括预约登记、扦样质检、称重计量、仓储分配、结算统计等环节。

#### 3.3.2 LangChain 实现结构

```
InOutBoundAgent
├── Chain: 入库流程链
│   ├── Step 1 — 预约登记 (Tool: 创建预约单)
│   ├── Step 2 — 车辆排队 (Tool: 排队叫号)
│   ├── Step 3 — 扦样质检 (Tool: 记录质检结果)
│   ├── Step 4 — 称重毛重 (Tool: 读取地磅)
│   ├── Step 5 — 卸粮入库 (Tool: 分配仓房 + 记录入仓)
│   ├── Step 6 — 称重皮重 (Tool: 读取地磅)
│   ├── Step 7 — 结算 (Tool: 计算净重 + 扣量)
│   └── Step 8 — 生成凭证 (Tool: 打印入库单)
├── Chain: 出库流程链
│   ├── Step 1 — 出库指令接收 (Tool: 读取销售订单/调拨单)
│   ├── Step 2 — 车辆排队
│   ├── Step 3 — 出仓装粮 (Tool: 指定出仓仓房)
│   ├── Step 4 — 称重毛重
│   ├── Step 5 — 结算
│   └── Step 6 — 生成出门证
├── Tools:
│   ├── create_appointment(data) → 预约单号
│   ├── record_inspection(inspection_data) → 质检记录
│   ├── read_scale(device_id) → 当前重量
│   ├── allocate_silo(grain_type, quantity) → 推荐仓房
│   ├── get_silo_capacity(silo_id) → 当前库存/容量
│   └── calculate_settlement(gross, tare, grade) → 结算结果
├── Memory:
│   └── 会话记忆: 当前正在执行的出入库流程状态
└── Active Learning:
    └── 根据历史数据优化仓房分配策略
```

#### 3.3.3 核心字段

**入库单字段：** 预约编号、承运人、车牌号、粮食品种、产地、检验等级、毛重、皮重、净重、扣量量、结算金额、仓房号、入库时间。

**出库单字段：** 出库指令号、销售合同号、客户信息、粮食品种、出库仓房、毛重、皮重、净重、出库时间。

### 3.4 报表分析 Agent (ReportAgent)

#### 3.4.1 职责

根据用户查询或定时任务，从各数据源汇总数据，生成粮库运营报表、粮情报表、出入库统计报表及数据分析报告。

#### 3.4.2 LangChain 实现结构

```
ReportAgent
├── Chain: 报表生成链
│   ├── Step 1 — 意图理解 (LLM: 解析用户自然语言查询)
│   ├── Step 2 — SQL/Template 选择 (LLM: 确定报表类型 + 参数)
│   ├── Step 3 — 数据查询 (Tool: 执行 SQL / 调用聚合 API)
│   ├── Step 4 — 数据分析 (LLM: 分析趋势/异常/对比)
│   └── Step 5 — 可视化生成 (Tool: 生成 ECharts 配置)
├── Sub-chains:
│   ├── DailyReportChain     — 日报数据聚合
│   ├── MonthlyReportChain   — 月报同比环比
│   ├── InventoryReportChain — 库存盘点（账实对比）
│   └── CustomQueryChain     — 自由查询 + NL2SQL
├── Tools:
│   ├── query_database(sql) → 查询结果
│   ├── generate_chart(data, chart_type) → ECharts JSON
│   ├── export_pdf(content) → PDF 文件下载
│   └── compare_period(current, previous) → 同比/环比结果
└── Memory:
    └── 模板记忆: 常用报表模板 + 用户偏好
```

#### 3.4.3 支持的报表类型

| 报表类型 | 周期 | 数据来源 | 主要指标 |
|---------|------|---------|---------|
| 粮情日报 | 每日 | 粮情 Agent | 最高/最低/平均粮温、湿度、异常统计 |
| 出入库日报 | 每日 | 出入库 Agent | 入库量/出库量/车次/等级分布 |
| 库存月报 | 每月 | 出入库 + 盘点 | 期末库存、月周转率、损耗统计 |
| 作业报告 | 按需 | 作业 Agent | 作业次数、能耗、费用、效果评估 |
| 质量分析 | 按需 | 质检数据 | 等级分布、主要质量问题、趋势 |
| 综合运营 | 按需 | 全部 Agent | 吞吐量、设备利用率、人员效率 |

#### 3.4.4 输出示例（查询转 SQL）

```
用户: "上个月哪个仓的粮温最高？"
→ NL2SQL: SELECT silo_id, AVG(temperature) as avg_temp
           FROM grain_metrics
           WHERE timestamp >= '2025-05-01' AND timestamp < '2025-06-01'
           GROUP BY silo_id ORDER BY avg_temp DESC LIMIT 1
→ 回答: "上个月 S-07 仓平均粮温最高，为 28.6°C，建议对该仓重点监测。"
```

## 4. AgentScope 编排设计

### 4.1 Agent 注册与发现

```python
# orchestrator.py — 伪代码示意
from agentscope import AgentScopeOrchestrator, AgentMeta

orchestrator = AgentScopeOrchestrator(name="grain_orchestrator")

# 注册子 Agent
orchestrator.register_agent(
    name="grain_condition",
    agent_class=GrainConditionLangChainAgent,
    description="粮情分析：传感器数据采集、异常检测、预警",
    capabilities=["sensor_query", "anomaly_detection", "trend_forecast"],
    priority=1
)
orchestrator.register_agent(
    name="operation",
    agent_class=IntelligentOperationLangChainAgent,
    description="智能作业：方案生成、设备控制、过程监控",
    capabilities=["ventilation", "fumigation", "temp_control"],
    priority=2
)
orchestrator.register_agent(
    name="inoutbound",
    agent_class=InOutBoundLangChainAgent,
    description="出入库管理：预约、质检、称重、结算",
    capabilities=["inbound", "outbound", "settlement"],
    priority=2
)
orchestrator.register_agent(
    name="report",
    agent_class=ReportLangChainAgent,
    description="报表分析：数据查询、报表生成、可视化",
    capabilities=["query", "report", "chart"],
    priority=3
)
```

### 4.2 消息路由模式

| 模式 | 适用场景 | 实现方式 |
|------|---------|---------|
| **点对点** | 粮情 Agent → 作业 Agent 推送异常 | AgentScope 直接消息 |
| **广播** | Orchestrator 向所有 Agent 下发天气预警 | Pub/Sub Channel |
| **请求-响应** | 用户查询 → Orchestrator → 报表 Agent | 同步调用 |
| **编排链** | 入库流程: 出入库 → 质检 → 称重 → 结算 | AgentScope Pipeline |

### 4.3 典型协作流程

#### 4.3.1 异常响应流程

```
1. 粮情 Agent 检测到 S-01 仓温度异常上升 (2°C/4h)
2. 粮情 Agent → 发送 alert 给 Orchestrator
3. Orchestrator → 请求 作业 Agent 分析原因并建议方案
4. 作业 Agent:
   a. 查询天气 (Tool: 外部气象 API)
   b. 查询设备状态 (Tool: 设备控制)
   c. 判断为"高温天气导致仓壁传热"
   d. 建议"夜间机械通风降温，22:00-02:00"
5. 作业 Agent → 返回方案给 Orchestrator
6. Orchestrator → 仓储管理员确认 (或自动执行规则)
7. 作业 Agent → 执行通风 (Tool: control_device)
8. 监控执行，完成后更新粮情 Agent 的状态
```

#### 4.3.2 入库流程

```
1. 司机到场 → 门卫扫描二维码
2. Orchestrator 创建入库会话 → 通知 出入库 Agent
3. 出入库 Agent: 预约单校验 → 车辆排队
4. 出入库 Agent → 质检员 App 通知 → 扦样
5. 出入库 Agent: 录入质检结果 (Tool: record_inspection)
6. 出入库 Agent: 称毛重 (Tool: read_scale)
7. 出入库 Agent: 分配仓房 (Tool: allocate_silo)
8. 卸粮完成 → 称皮重 → 结算
9. 报表 Agent: 自动更新日报统计数据
```

## 5. LangChain 子 Agent 实现要点

### 5.1 通用基类

```python
from langchain.agents import AgentExecutor, create_openai_tools_agent
from langchain.memory import ConversationBufferMemory
from langchain.tools import BaseTool

class BaseGrainAgent:
    """所有子 Agent 的基类"""

    def __init__(self, llm, tools: list[BaseTool], system_prompt: str):
        self.llm = llm
        self.tools = tools
        self.memory = ConversationBufferMemory(
            memory_key="chat_history",
            return_messages=True,
            k=20  # 保留最近 20 轮
        )
        self.agent = create_openai_tools_agent(llm, tools, system_prompt)
        self.executor = AgentExecutor(
            agent=self.agent,
            tools=tools,
            memory=self.memory,
            verbose=True,
            max_iterations=10,
            early_stopping_method="generate"
        )

    async def run(self, input_text: str, context: dict = None) -> str:
        """运行 Agent"""
        return await self.executor.ainvoke({
            "input": input_text,
            "context": context or {}
        })
```

### 5.2 AgentScope 集成桥接

```python
# bridge.py — LangChain Agent → AgentScope Agent 适配器
from agentscope.agent import AgentBase

class LangChainBridgeAgent(AgentBase):
    """将 LangChain AgentExecutor 包装为 AgentScope Agent"""

    def __init__(self, name: str, langchain_executor: AgentExecutor, **kwargs):
        super().__init__(name=name, **kwargs)
        self.executor = langchain_executor

    async def reply(self, x: dict = None) -> dict:
        """AgentScope 消息接口"""
        input_text = x.get("content", "")
        context = x.get("context", {})
        result = await self.executor.ainvoke({
            "input": input_text,
            "context": context
        })
        return {
            "role": self.name,
            "content": result.get("output", ""),
            "metadata": result.get("intermediate_steps", [])
        }
```

## 8. 风险与对策

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| LLM 幻觉导致错误作业指令 | 设备损坏、安全风险 | 所有设备控制指令需经过"安全校验 Chain" + 人工确认开关 |
| Agent 间死锁 | 流程卡死 | Orchestrator 设置超时机制 + 回滚策略 |
| 传感器数据采集延迟 | 粮情分析滞后 | 引入消息队列缓冲，异步处理 |
| LLM 调用成本过高 | 运营成本超支 | 缓存常见查询，优先使用轻量模型处理常规任务 |
| 粮库网络环境差 | 设备控制失败 | 本地边缘计算 + 离线作业模式 |
