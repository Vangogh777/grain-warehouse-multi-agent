🚀 GLM-5 加速方案

一、现状

当前 GLM-5 单次推理耗时分布：

用户提问
  │
  ▼ 第1轮 (12s) → GLM-5 思考 → TOOL_CALL: get_sensor_data(S-07)
  │                 执行工具 (0s)
  ▼ 第2轮 (12s) → GLM-5 思考 → TOOL_CALL: get_weather()
  │                 执行工具 (0s)
  ▼ 第3轮 (12s) → GLM-5 思考 → TOOL_CALL: check_device()
  │                 执行工具 (0s)
  ▼ 第4轮 (12s) → GLM-5 思考 → FINAL: 结论
  │
  总计: ~48s（4次LLM调用）

瓶颈： 推理模型每轮都要重新思考，4轮就是48秒。而工具执行本身是毫秒级的。

二、优化方案

方案 A：工具自动推断 + 并行执行（最快，半小时实现）

不再让 LLM 决定调什么工具，而是根据场景规则自动推断并并行执行所有工具，最后只让 GLM-5 做一次分析。

用户提问 → 场景检测 → 自动推断工具列表 → 并行执行全部工具 → GLM-5 只做分析（1轮） → 结论 
# base_agent.py 自动工具注入逻辑
TOOL_MAP = {
    "ventilation": ["get_sensor_data", "get_silo_info", "get_weather", 
                     "check_device_status", "get_electricity_price"],
    "grain_analysis": ["get_sensor_data", "get_silo_info"],
    "inoutbound": ["query_today_inbounds", "query_today_outbounds"],
    "quality": ["query_sample_records", "query_quality_alerts"],
    "report": ["query_inventory", "analyze_anomaly_silos"],
}

def auto_execute_tools(scenario, silo_id=None):
    """自动执行场景所需工具，不经过 LLM 决策"""
    tool_names = TOOL_MAP.get(scenario, [])
    results = {}
    for name in tool_names:
        tool = find_tool(name)
        params = {"silo_id": silo_id} if silo_id else {}
        results[name] = tool._run(**params)
    return results
对比当前方案 A
LLM 调用次数3~4 轮1 轮
总耗时~48s~15s（1次推理）
工具执行串行，每轮等 LLM并行，毫秒级

优点 简单可靠，耗时降 70%

缺点 工具调用是固定规则，不灵活

方案 B：一次性输出全部工具调用（稍灵活，1天）

修改 prompt，让 GLM-5 在一次回复里输出所有需要的工具，然后我们并行执行。

当前 prompt:
  思考 → TOOL_CALL: xxx → 结果 → 思考 → TOOL_CALL: yyy → 结果 → FINAL

优化后的 prompt:
  请分析需要哪些工具，一次性输出所有 TOOL_CALL，用 --- 分隔。
  然后我把所有结果给你，你再做分析。
  
  输出格式：
  TOOL_CALL: get_sensor_data(S-07)
  TOOL_CALL: get_weather()
  TOOL_CALL: check_device_status(S-07)
  ---
  [等待工具结果...]
  ---
  FINAL: 基于以上数据，分析结论...
一轮 LLM 调用 → GLM-5 输出 N 个 TOOL_CALL → 并行执行 N 个工具 → 再一轮 LLM 调用分析 → 结论
对比当前方案 B
LLM 调用次数3~4 轮2 轮
总耗时~48s~25s

优点 保留 LLM 决策灵活性

缺点 推理模型可能不按格式输出，实现稍复杂

方案 C：双模型混合（最理想，需额外模型 API）

工具调用用快模型（非推理），深度分析用 GLM-5。这是最好的方案，但需要一个额外的非推理模型 API。

用户提问 → 快模型（如 Qwen2.5） → 调工具、收集数据 → GLM-5 深度分析 → 结论

如果你能找到另一个非推理模型的 API（比如本地 Ollama 跑 Qwen2.5），用这个方案效果最好：

  • 快模型：5 秒内完成工具调用 + 数据收集 - ✅
  • GLM-5：15 秒深度分析 - ✅
  • 总耗时：~20 秒，比现在的 48 秒快一倍多 - ✅

三、推荐实施顺序

优先级方案时间预期效果
P0方案 A：自动工具推断 + 并行执行30 分钟48s → ~15s
P1方案 B：一次性输出全部工具1 小时48s → ~25s
P2方案 C：双模型混合取决于获取新模型 API48s → ~20s

建议：先做方案 A，30 分钟见效，从 48 秒降到 15 秒左右。后续有精力再做 B 或 C。
